
Here is a risk-focused test matrix organized by your requested quality characteristics: **Functionality**, **Data Integrity**, and **Security**.

## 2. Data Integrity Risks

* **Corruption during Ingestion:** Calculate the cryptographic hash (e.g., SHA-256) of a document prior to upload and compare it with the stored file post-upload to ensure no byte corruption occurs during chunking or transfer.
* **Special Character & Long Filenames:** Test filenames containing special/legal characters (`Case_#123_Smith&Jones_v2.1(Final).pdf`), international UTF-8 characters (e.g., accent marks), and long paths (255+ characters). Ensure filenames are sanitized without stripping essential context.
* **Concurrency & Duplicates:** Upload two files with identical names simultaneously from different sessions by the same paralegal, or upload the same file twice in rapid succession. Verify how the system handles versioning or collision without overwriting existing data.
* **Partial Upload Cleanup:** Sever the network connection mid-upload. Verify that incomplete/orphaned temporary file artifacts on the server storage or S3 bucket are purged and do not consume storage space or corrupt the user's workspace.
* **Audit Trail Immutability:** Verify that audit log records for document uploads cannot be modified, deleted, or backdated by users (including paralegals or higher-privileged roles).

## 3. Security & Confidentiality Risks

```
[ Paralegal Session ] ──► [ MIME / Header Check ] ──► [ AV / Malware Scan ] ──► [ Private Storage (Default Unshared) ]
                                                                                         │
                                                                           Access Control Check (RBAC/ABAC)
                                                                                         │
                                                                           ┌─────────────┴─────────────┐
                                                                           ▼                           ▼
                                                                  [ Uploader Session ]       [ Unauthorized User ]
                                                                       (200 OK)                (403 Forbidden)

```

* **Default Access Control (Isolation):**
* Right after upload, log in as another paralegal, attorney, or admin and attempt to view or download the document using the direct document URL or API endpoint.
* Confirm that access is strictly denied (`403 Forbidden`) until explicit sharing rules are applied.


* **MIME / Content-Type Spoofing:** Rename an executable file to `.pdf` (`malware.exe` $\rightarrow$ `malware.pdf`) or alter header magic bytes. Verify the server-side validator inspects file headers/magic numbers rather than relying solely on the file extension.
* **Malicious File Upload (AV Scanning):** Upload a test virus payload (e.g., EICAR test string embedded inside a `.docx` or `.pdf`). Verify the file is quarantined/blocked before hitting permanent storage, and an audit entry records the security failure.
* **Directory Traversal Attack:** Set filename to `../../../../etc/passwd.pdf` or payload paths during HTTP `POST` requests. Confirm the backend strips relative pathing and isolates storage to designated user directories.
* **Stored Cross-Site Scripting (XSS):** Embed JavaScript payloads inside standard file metadata (author, title) or inside `.txt` files. Verify that rendered document lists or previewers escape all output safely.
* **Direct Object Reference (IDOR):** Inspect the response after uploading a file. If a file ID or URI path (e.g., `/documents/10492`) is generated, attempt to increment/decrement the ID from a different user session to ensure private files cannot be enumerated.
