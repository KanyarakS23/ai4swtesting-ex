# Activity 1 – Step 1: A vague prompt

**Chatbot / model: Gemini 3.6 Flash** 

## Prompt

```text
Create tests for a file upload feature
```

## Response

Here is a comprehensive test suite for a file upload feature, organized by test categories.

## Functional & Boundary Tests

| Test Case ID | Test Scenario | Input / Action | Expected Result |
| --- | --- | --- | --- |
| **TC-01** | Single Valid File Upload | Upload a `.pdf` file (2 MB) | File uploads successfully; success notification displays; file appears in list/storage. |
| **TC-02** | Multiple Valid Files Upload | Select and upload 3 supported files simultaneously | All files upload successfully and render correctly in UI. |
| **TC-03** | Unsupported File Extension | Attempt to upload `.exe` or `.bat` file | Upload fails; error message states "Unsupported file format." |
| **TC-04** | File Size at Exact Limit | Upload a file exactly at the maximum allowed size (e.g., 10 MB) | File uploads successfully without error. |
| **TC-05** | File Size Exceeding Limit | Upload a file slightly over the limit (e.g., 10.1 MB) | Upload blocked; error message displays "File size exceeds the 10 MB limit." |
| **TC-06** | Zero-Byte / Empty File | Upload an empty `.txt` file (0 KB) | System rejects the file with an appropriate message ("File cannot be empty"). |
| **TC-07** | Duplicate File Upload | Upload the same file twice | System handles duplicates (either renames automatically or prompts user for overwrite). |
| **TC-08** | File Name with Special Characters | Upload file named `test_file!@#$%^&()_+.png` | File uploads cleanly; filename is correctly sanitized or preserved safely. |
| **TC-09** | File Name with Long Path/Title | Upload file with a 255+ character filename | System truncates UI display cleanly without breaking layout or backend storage. |

## User Experience (UI / UX) Tests

* **Drag-and-Drop Dropzone:** Verify hovering over the dropzone visually highlights the target area, and dropping files initiates the upload.
* **Progress Indicator:** Ensure a progress bar or percentage indicator updates in real time during large file uploads.
* **Cancel Upload:** Verify clicking "Cancel" mid-upload immediately stops request execution and cleans up temporary partial files.
* **Remove / Delete File:** Confirm users can remove an uploaded file before submitting the form.
* **File Preview:** Check that image thumbnails (JPEG, PNG) or file icons (PDF, DOCX) display properly after selection.

---

## Security Tests

```
   [ Client Upload ] ──► [ MIME & Extension Validation ] ──► [ Virus Scan ] ──► [ Secure Storage ]

```

1. **MIME Type Spoofing:** Rename an executable (`payload.exe`) to `payload.png` and upload it. The backend must inspect the binary signature/magic bytes and reject the file.
2. **Malicious Content / Malware:** Upload a test virus file (e.g., EICAR standard test file). System should quarantine or block the file via virus scanner.
3. **Path Traversal Attack:** Upload a file named `../../../../etc/passwd`. Verify storage paths are sanitized to prevent directory traversal.
4. **Cross-Site Scripting (XSS):** Upload an HTML or SVG file containing `<script>alert('XSS')</script>` and attempt to view/open it directly in the browser. Verify context header is set to `Content-Disposition: attachment` or content is sanitized.
5. **Restricted Direct Access:** Access the raw storage URL of an uploaded private file without an active user session; system must return `401 Unauthorized` or `403 Forbidden`.

---

## Performance & Edge Cases

* **Network Interruption:** Disconnect network connection during upload; ensure system displays a retry prompt without freezing the UI.
* **Concurrent Uploads:** Test multiple users uploading maximum file sizes simultaneously to verify backend queueing and resource limit stability.
* **Timeout Handling:** Test behavior under slow network conditions (3G throttling) to confirm timeouts are handled gracefully.
